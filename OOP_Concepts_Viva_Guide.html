Part 1: The Four Core OOP Pillars
1. Abstraction model/Vehicle.java (Lines 25–88)

Concept: Hiding internal implementation complexity and enforcing an abstract contract that all subclasses must satisfy.

public abstract class Vehicle implements ParkingFeeCalculator, PrintableReceipt {
    // Abstract method — no generic formula exists; subclasses must provide it!
    public abstract double calculateParkingFee(long durationHours);
    public abstract String getVehicleType();
}
🗣️ What to say to Professor: “Sir, a Vehicle is an abstract concept. You cannot park a generic vehicle without knowing whether it is a Bike, Car, or Truck because each has distinct physical footprint and tariff rates. Thus, Vehicle is an abstract class with abstract method calculateParkingFee() enforced on subclasses.”

6. Multidimensional Array (2D Grid) & Recursion model/ParkingLot.java (Lines 28–118)

Physical facility is modeled as a 2D matrix: ParkingSlot[floorIndex][slotIndex]. Finding a free slot uses recursive grid search:

private ParkingSlot searchGridRecursively(SlotType slotType, int floorIndex, int slotIndex) {
    if (floorIndex >= totalFloors) return null; // Base Case 1: All floors searched
    if (slotIndex >= slotsPerFloor) return searchGridRecursively(slotType, floorIndex + 1, 0);

    ParkingSlot slot = parkingGrid[floorIndex][slotIndex];
    if (slot != null && slot.isAvailable() && slot.getSlotType() == slotType) {
        return slot; // Base Case 2: Free matching slot found!
    }
    return searchGridRecursively(slotType, floorIndex, slotIndex + 1); // Recursive Step
}

8. Multithreading, Synchronization & wait() / notifyAll() threads/ParkingMonitor.java, ReportGenerator.java, ParkingRequestQueue.java
  • Extending Thread: ParkingMonitor extends Thread with setDaemon(true) and safe shutdown via volatile boolean running.
  • Implementing Runnable: ReportGenerator implements Runnable + thread.join().

  • wait() & notifyAll(): Inside ParkingRequestQueue, waiting threads call wait() until a vehicle leaves and triggers notifyAll().

Part 4: Top 5 Viva Questions & Answers
Q1. Is Java Pass-by-Reference or Pass-by-Value?
Answer: Java is strictly Pass-by-Value at all times. When passing primitives, a copy of the value is passed. When passing object references, a copy of the reference address pointer is passed by value. Reassigning the pointer inside the method doesn't change the caller's reference, but mutating properties through that pointer does. (Demonstrated in demo/ArgumentPassingDemo.java).
Q2. What is the difference between Thread's start() and run()?
Answer: Calling run() executes the code synchronously in the current thread like a standard method call. Calling start() instructs the JVM and OS to allocate a new call stack and launch a distinct background thread of execution. (Demonstrated in threads/ParkingMonitor.java).
Q3. Why use try-with-resources instead of explicit finally blocks?
Answer: Any class implementing AutoCloseable (e.g. FileWriter or FileOutputStream) is guaranteed to close cleanly upon block exit, even if unexpected exceptions occur, preventing file lock and memory leaks. (Demonstrated in io/ParkingReportWriter.java).
Q4. Can an Abstract Class have a constructor?
Answer: Yes! Vehicle has constructors. While you cannot instantiate it directly via new Vehicle(), its constructor is invoked by subclass constructors via super() to initialize common properties like vehicle number and timestamp.
Q5. Why is the payment collection on the Admin/Operator screen?
Answer: In real parking facilities, drivers do not access database systems directly. The exit boom barrier has an operator booth terminal where the attendant verifies the vehicle, states the calculated tariff, collects payment (Cash/UPI/Card), records the transaction in MySQL, prints the tax receipt, and releases the slot.
